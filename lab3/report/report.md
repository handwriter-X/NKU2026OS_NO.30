# Lab3 实验报告：中断与异常

> P1/P2/P3 已完成，2026-11-05 综合验证通过。本报告基于本地指导书和自建验证。

## 1. 实验目标与整体逻辑

本实验承接 lab2 的内存初始化和页分配功能，建立完整的 Trap 处理链。实现顺序为：先把被打断代码的现场保存为 frame，再让汇编入口按 ABI 调用 C 函数，恢复现场并 sret；随后补齐时钟中断处理；最后实现非法指令和断点异常处理，使内核可以按异常指令实际长度推进执行位置。

这种顺序先解决底层上下文是否可信，再解决具体事件语义。若恢复 sp 或 epc 错误，即使 C handler 输出正确，也不能认为 Trap 处理成功。

## 3. P1：Trap 上下文恢复与入口

### 3.1 Specification 与 Prompt 设计

P1 的 Specification 明确 frame 中每个槽位的含义，强调 2 号槽存原始 sp，规定 CSR 先恢复、sp 最后恢复，禁止硬编码指令宽度、二次分配栈和在宏内返回。入口规范要求把当前 sp 作为 a0，用 call 调用 trap，并保持 frame 栈位置。原始提示词与个人操作/答辩资料按用户要求保存在仓库外的工作区 `OS/lab3/`，不随仓库提交；本报告独立说明其设计与实现。

Prompt 限定实际修改 `trapentry.S` 中两个目标位置，保留 SAVE_ALL、frame 布局、__trapret 与 sret，不扩展到其他函数重构，并指定署名 `lab3: 2414067`。这些边界避免 AI 用错误的“全部寄存器等价恢复”或“强制返回用户态”模板。

### 3.2 核心实现

`SAVE_ALL` 按指导书保存通用寄存器及 sstatus/sepc/stval/scause。`RESTORE_ALL` 使用 s0/s1 临时读取 32/33 号槽并写回 CSR，再恢复 x1 和 x3～x31，最后通过 2 号槽恢复 x2。x0 恒为零，无须恢复；诊断用 stval/scause 无须回写。全部偏移和访问宽度用 REGBYTES 与 LOAD 表达。

`__alltraps` 保存后执行 `mv a0, sp` 和 `call trap`。调用返回地址正好位于 __trapret，恢复时再次读取 frame 的 epc，可见 C handler 对返回位置的更新。最终 sret 按保存的 SPP 返回权限，并按 SPIE 恢复 SIE，不在汇编恢复宏里手工清改这两个位。

## 4. P2：时钟中断

### 4.1 Specification 与 Prompt 设计

Specification 把处理行为分成三类。Supervisor 定时器中断必须先重设事件，再增加 ticks；ticks 为 TICK_NUM 的倍数时复用 print_ticks 输出，并用独立的统计行数计数器决定何时关机，先输出再关机且只能请求一次。其他已定义中断只报告类型与原因码，未知原因只调用 print_trapframe。所有分支必须保持 frame 不变并返回统一流程，禁止在 handler 中开启中断或等待事件。

Prompt 将主要修改范围限定为 `interrupt_handler()`，明确 `exception_handler()` 保持空实现，保护 trap/trap_dispatch/print_trapframe/idt_init/print_ticks、struct trapframe、clock.c 与 sbi.h，并指定 `lab3: 2411520`。这里把顺序、状态不变性和边界条件写入 Spec，而非只要求“打印 ticks”，以避免 AI 漏掉事件重设、错误用绝对 ticks 触发关机或实现不必要的异常逻辑。

### 4.2 核心实现与接入

`(tf->cause << 1) >> 1` 去掉 scause 的最高中断标志位，保留原因码。IRQ_S_TIMER 分支依次执行 clock_set_next_event、ticks 自增、整百统计。模块内静态变量 printed_lines 累计实际打印行数；shutdown_requested 在调用 SBI 前置位，因此即使关机接口返回，后续中断也不会重复请求关机。框架常量 TICK_NUM=100、SHUTDOWN_AFTER=10 沿用 P1 设置。

其余 13 个已定义原因覆盖 U/S/H/M 软件中断、U/H/M 定时器中断、U/S/H/M 外部中断以及协处理器、Host 中断，只输出一行类型和原因码。未知原因通过完整 frame 诊断兜底。handler 不改动 epc/status/cause 等字段，也不直接操作中断使能。

实际运行需要两项框架接入：在 init.c 中按 idt_init → clock_init → intr_enable 的顺序启动；在 libs/sbi.c 中为原头文件已声明的 sbi_shutdown 增加 legacy SBI 8 包装。没有改动 clock.c、sbi.h、frame 布局或 P1 汇编。trap.c 中除了 interrupt_handler 本体，其他函数全部保持原样。

## 5. P3：非法指令与断点异常

### 5.1 Specification 与 Prompt 设计

P3 Spec 区分“需要跳过的两类异常”和“仅诊断的其他异常”。非法指令与断点必须输出类型和原始 epc，按该地址指令编码的低两位识别长度：低两位不是11时加2，是11时加4。Spec 只允许修改 epc，禁止改 status/cause、开中断、panic、关机或循环重试；其他异常仅调用 print_trapframe，保持整个 frame 不变。

Prompt 将生产代码修改限定为 exception_handler，要求保留已完成的 interrupt_handler，并保护其他分发、输出、初始化函数、frame 布局和 clock/SBI 头文件。署名使用 `lab3: 2412267`。这种写法把异常分类、指令长度、状态边界与统一返回流程联系起来，避免对所有异常固定加4或通过修改返回权限“修复”死循环。

### 5.2 核心实现

switch 依据 tf->cause 选择 Illegal instruction 或 Breakpoint，输出类型以及处理前的 epc。随后只读取 `*(const volatile uint16_t *)tf->epc`，用低两位决定2/4字节增量，写回 tf->epc。读取前半字足以完成题目要求的长度判断，并且不会为了取低两位而强制进行32位对齐读取。其他原因直接输出 frame 并返回，不读取 epc 指向的指令。

输出使用两行格式：`Exception type: Illegal instruction` 或 `Exception type: Breakpoint`，随后为 `Exception epc: 0x` 与16位十六进制地址。离线指导书提到“规定格式”，但本地正文与提供的 Prompt 未给出更具体模板；此处采用明确的类型和地址格式，完整官方框架/评分程序尚未取得。

本实验按 Spec 处理16/32位编码，不实现48位及更长扩展指令的通用解码，也不为损坏的不可读 epc 增加通用取指故障恢复。对未处理的异常仅诊断后原址返回，若原因持续存在，可能再次陷入；这符合本节要求，不代表实现了通用异常恢复策略。

## 6. 知识点与原理对应

| 实验机制 | 对应原理 | 含义、联系与差异 |
| --- | --- | --- |
| SAVE_ALL/RESTORE_ALL | 上下文保护 | 保存被打断执行流，而非已实现任务调度；Trap 发生时没有普通函数调用的 caller-saved 保护前提。 |
| frame | CPU 状态的内存表示 | C 与汇编通过固定布局共享现场；sp 的恢复顺序受基址寻址约束。 |
| Direct stvec 与软件分发 | 中断组织 | 一个硬件入口加软件原因分发，不等同于硬件每类中断的独立向量。 |
| sstatus/sret | 权限与中断状态恢复 | 按保存的 SPP/SPIE 返回；Trap 不必来自用户态，也不一定改变当前权限级。 |
| sepc | 异常恢复/指令重启 | 记录返回位置；异步时钟通常不推进它，同步异常是否跳过取决于语义。 |
| clock_set_next_event | 单次定时器与周期事件 | SBI 每次只设一次事件，软件必须重设才形成周期；当前做法是“现在+间隔”，存在处理开销导致的漂移。 |
| ticks 与 printed_lines | 时间事件与统计策略 | 前者累计中断次数，后者累计输出次数，含义不同；约 10ms 的目标间隔不意味着严格墙钟计时。 |
| SIE 与 STIE | 全局与来源屏蔽 | 两级使能一起满足才可响应；handler 不自行打开全局使能，避免无准备的嵌套。 |
| shutdown_requested | 副作用幂等 | 状态在调用前设置，即使外部接口返回也不重复请求；并不构成多核原子同步。 |
| 非法指令/断点与epc推进 | 同步异常与恢复策略 | 同步异常由当前指令触发；本实验选择报告后跳过，实际OS也可能终止进程、向调试器报告或模拟执行。 |
| 指令低两位与半字读取 | 可变长指令编码 | RISC-V压缩指令为16位，常规指令为32位，返回增量必须匹配编码；本实验只覆盖这两种长度。 |

本阶段的上下文保存不等于完整进程切换：没有选择新任务、切换地址空间或维护 PCB。统一入口也不等于向量模式。本实验的内核栈处理不提供完整用户态双栈切换。

## 7. 重要但未覆盖的 OS 原理

进程调度、系统调用与参数检查、内存保护和完整缺页处理、多核同步、设备中断确认、浮点/向量状态管理及嵌套 Trap 栈保护。当前普通中断分支只是分类提示，没有驱动级确认/清除来源；时钟计数尚未驱动调度器。本次没有扩展用户态双栈切换或其他challenge。

## 8. 实验体会与最终状态

Trap正确性需要同时满足保存布局、ABI调用、事件语义与硬件返回四项约束。控制台输出正确不足以证明恢复正确，因此用真实寄存器哨兵检查保存/恢复、用frame逐字节比较约束handler副作用，再用异常之后持续运行到关机验证整条链路。主机行为测试适合边界和接口返回条件，QEMU补充真实CSR、指令异常和SBI链路，二者互补。

P1/P2/P3的必做功能和自建综合验证已完成，根目录及lab3 README已更新；个人操作说明、提示词、知识点梳理仅保留在仓库外OS/lab3。完整官方源码包与评分程序不可用的限制仍如实保留。本轮工作没有执行commit或push。
